### 初始化到 Diff 显示流程梳理
- 已基于当前源码确认主链路：`extension.activate` → `GitkViewProvider.initializeBackground` → `refresh`/`refreshInternal` → `refreshSelectors`（仓库、分支）→ `getGitCommits`（提交及 `buildGraph`）→ 自动 `selectCommit` → `getCommitFiles`（`diff-tree --raw`）→ `DiffReader.prepare`（`git cat-file --batch`）→ `MultiDiffPanel` 发布快照并由 Monaco DiffEditor 渲染；Changed Files 列表在收到 `rendered` 后才解除 loading。
- 澄清：`refreshSelectors` 虽全量发现仓库（含子模块），但只对 `selectedRepositoryPaths[0]` 调用 `getGitBranches`；多仓库选择时直接将 `branches` 置空，因此不加载全部仓库的分支。
- 文案调整：`getGitRepositoriesInternal` 的进度文案由“初始化仓库”改为“异步读取工作区仓库”，因为代码通过 `Promise.all(...resolveRepositoryRoot)` 异步读取工作区目录对应的仓库；子模块扫描仍单独显示。
- 初始化顺序调整：`refreshInternal` 进入首次加载时立即 `void refreshInitialSelectorsInBackground`，随后快速读取当前仓库、当前分支和 commit；删除 commit 加载完成后的后台刷新调用，后台刷新结果仅替换候选列表，不覆盖当前选中仓库/分支。
- 子模块进度文案调整为“异步读取仓库中的子模块...”及“已读取仓库中的子模块 N 个...”，与 `collectSubmoduleRepositories()` 的实际流程一致，不再使用容易误解为独立扫描动作的“正在扫描子模块”。
- 首次加载调整：确定当前仓库后先刷新仓库候选项；仅当仓库选项集合实际变化时，才启动当前仓库的分支刷新。普通刷新同样在 `refreshSelectors` 中比较仓库选项（path/label/description/hasSubmodules），仓库刷新但选项相同时保留现有分支列表，不触发分支读取；分支选择器渲染已与仓库选择器统一：`renderSelectors` 无论 loading 与否都先渲染当前候选项，再仅叠加 loading 状态，不再用仅含当前分支的 loading 占位内容覆盖已到达的候选数据。
- 仓库异步刷新统一保留当前选中仓库：`keepSelectedRepositoryOption` 在增量回调和最终结果中补回选中项；首次初始化与普通 `refreshSelectors` 都先显示已有/增量仓库项，`reposLoading` 期间不清空弹窗，且不修改 `selectedRepositoryPaths`。
- 仓库选项变化时，普通刷新先清空旧分支候选项，保留已选分支值；并行读取新仓库当前分支/HEAD，当前分支返回后立即写入分支列表；完整分支列表异步返回后合并，继续保留已选分支选项。
- 修复首次初始化分支刷新被仓库刷新回调阻塞：当前仓库和当前分支确定后立即独立启动 `refreshInitialBranchesInBackground` 与 `refreshInitialRepositoriesInBackground`；仓库结果不再触发分支刷新，避免等待仓库扫描完成。
- 仓库选项变化时，`refreshSelectors` 先并行获取当前仓库的当前分支/HEAD 与完整分支请求；当前分支结果立即增量写入分支列表，完整 `getGitBranches` 返回后再合并候选项，同时保留原已选分支；仓库刷新不再阻塞分支首项显示。
