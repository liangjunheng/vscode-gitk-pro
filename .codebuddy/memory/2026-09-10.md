# 2026-09-10

## 两个 UI 问题的定位结论（vscode-gitk）

### 仓库下拉看不到"当前仓库"被选中
- 数据链路是对的：`renderRepositoryOptions`（`src/webview/selectorBarSubPanel.ts`）会按 `selectedRepositoryPaths` 算出 `selectedValue`，给选项加 `selected` class 并置 `radio.checked=true`。
- 根因在样式：仓库下拉把 `::before` 的 ✓ 和 radio 同时隐藏了（`.dropdown-option.selected::before{display:none}` + `#repositoryDropdown .dropdown-option input{display:none}`），且没有 `.selected` 背景兜底；分支下拉靠可见 checkbox 兜底所以正常。
- 修法方向：给 `#repositoryDropdown .dropdown-option.selected` 补选中态（菜单选中背景/前景，或恢复 ✓）。

### 点 commit / push 后 Commit 面板消失
- `CommitPanel` 与 `MultiDiffPanel` 都用 `ViewColumn.Active` 创建 → 同一个编辑器组竞争"当前显示"；`CommitPanel.show()/focus()` 才 `reveal()`，`update()` 只 postMessage，`isVisible()` 只判 panel 对象是否存在。
- commit 路径抢占点：`runCommit()` 里无条件 `this.openDiff(this.selectedPath)`（gitkViewProvider.ts 约 1715 行）。
- push 路径：收尾 `forceRefreshCurrentSelection()` → `onSelectedCommitChanged` → 命中 revealDiff / restoreDiffPanelOnViewVisible 时 `openDiff()`；`pull` 默认勾选 → `git switch/pull` 改 HEAD 会再走一遍该链路。
- 修法方向：删除 runCommit 里与提交无关的 openDiff；操作结束后由 CommitPanel 自己 `reveal()`（focus 语义）回到前台。

## 已实施（问题 1）
- `src/webview/selectorBarSubPanel.ts`：在隐藏 radio 的规则前补两条仓库下拉选中态规则——恢复 `.selected::before` 的 ✓，并给 `.selected` 加 menu-selection 背景/前景；特异性相同且靠后，可覆盖第 64 行的 `display:none`。`npm run compile` 通过。
- 已实施（问题 2 前半）：删除 `runCommit()` 里的 `this.openDiff(this.selectedPath);`（原 1715 行）。提交后 Diff 内容刷新由 `forceRefreshCurrentSelection()` → `selectWorkingTreeChanges`/`setCommitFiles` 以 `revealDiff=false` 驱动，只更新数据不 reveal。`npm run compile` 通过。
- 已实施（问题 2 后半）：`runCommit` 的 finally 与 `runCommitPanelPush` 的 try/catch 之后各加 `this.commitPanel.focus(...)`（commit 用触发仓库、push 用根仓库），把"显示权归触发者"落到操作生命周期结束点；`CommitPanel.focus()` 注释补明它会 reveal 回前台。`npm run compile` 通过。
- 未做（可选）：把两个面板拆到不同编辑器组（Commit `ViewColumn.One` / Diff `ViewColumn.Beside`），或给 `MultiDiffPanel.show()` 加 `preserveFocus`，属布局产品决策。
