## 功能: 仓库/分支下拉按钮 loading 状态 (含竞态修复)
- 需求: 仓库/分支扫描未完成时, 对应下拉按钮显示 loading spinner
- 根因: `refreshInternal` 的 `setLoading(true)` 触发 `schedulePushState` (queueMicrotask), 该 `stateUpdate` 携带旧仓库数据; `refreshSelectors` 发 `reposLoading` 消息后 yield, microtask 随即触发 `stateUpdate`, webview `renderSelectors` → `renderRepositoryOptions` 用旧数据清除 spinner
- 修复: AppState 新增 `reposLoading`/`branchesLoading` 布尔字段, `pushStateToWebview` 携带; webview `renderSelectors` 在 `reposLoading`/`branchesLoading` 为 true 时跳过 `renderRepositoryOptions`/`renderBranchOptions`
- Provider 设置时机:
  - `refreshInternal` 开头: `store.setState({ reposLoading: false, branchesLoading: false })` 清除残留
  - `refreshSelectors`: 开头发 `reposLoading` 消息 + `store.setState({ reposLoading: true })`; repos batch 内 `reposLoading: false`; 分支前发 `branchesLoading` + `branchesLoading: true`; branches batch 内 `branchesLoading: false`
  - `refreshSelectedRepositoryBranches`: 开头发 `branchesLoading` + `branchesLoading: true`; branches batch 内 `branchesLoading: false`
  - `selectRepositories`: `store.setState({ branchesLoading: true })` 在 `postMessage` 之前
- abort 处理: early return 仅在 `isRefreshCurrent(generation)` 为 true 时清除对应 flag (非新 refresh 取代时才清; 新 refresh 起时不动, 由新 refresh 接管)
- CSS: `.dropdown-spinner` (10px 旋转圆环 + `@keyframes dropdown-spin`); HTML 初始 label 内嵌 spinner; `setRepositoryLoading`/`reposLoading`/`branchesLoading` handler 均用 `innerHTML` 注入 spinner
