## vscode-gitk: resolveCommitRefs 批量化

- 修复: resolveCommitRefs 从逐个 Promise.all 改为单次 `git rev-parse ref1^{commit} ref2^{commit} ...` 批量调用
- 部分失败处理: catch 块从 error.stdout 提取有效 40 位 hex 哈希 (正则过滤)
- getGitCommits totalOps 从 `refs.length + 1` 改为 `2` (1 resolve + 1 log)
- resolveCommitRefs 移除 onProgress 参数 (单次调用无需逐个报进度)

## vscode-gitk: 首次加载 + 加载更多速度优化
- 跳过 resolveCommitRefs: refs 直接传给 git log (省 1 次 git rev-parse 调用)
- 提取 parseLogOutput + buildRefsByCommit 公共函数, 消除 getGitCommits 和 getGitCommitsByHashes 间重复代码
- 新增 getCommitHashes(rootUri, refs, limit=10000): git rev-list --topo-order 预取全量 hash (仅 hash 无格式化, 快)
- 新增 getGitCommitsByHashes(rootUri, hashes): git log --no-walk 按 hash 直接取数据, O(101) 无遍历
- getGitCommitsByHashes 输出按输入 hash 顺序排序 (--no-walk 不保证顺序)
- refreshInternal: 首次加载时 git log + getCommitHashes + getWorkingTreeChanges 三路并行
- refreshBranchCommits: git log + getCommitHashes 两路并行
- loadMoreCommits: 优先用 allCommitHashes.slice(skip, skip+101) + getGitCommitsByHashes (O(101)); allCommitHashes 耗尽时回退 git log --skip (O(N), 适用于 >10000 提交的仓库)
- hasMoreCommits: allCommitHashes.length > rawCommits.length || page.length > COMMIT_PAGE_SIZE
- gitkViewProvider 新增 allCommitHashes 字段, refreshInternal/refreshBranchCommits/early-return 均重置

## vscode-gitk: 后台预取 + 渲染优化 (第五轮)
- 后台预取: 首页/加载更多完成后立即在后台预取下一页 (startPrefetch), 用户触发"加载更多"时数据已就绪, 无 git 进程等待

- 渲染优化: appendRows 用 list.children 索引替代 querySelector 逐行查找, O(N²)→O(N)

- 优化: 新增 getFirstRepoPath() 从 Git API 瞬间获取首个仓库路径 (无 git 命令), 并行启动 refreshSelectors + getGitCommits(HEAD) + getCommitHashes(HEAD) + getWorkingTreeChanges, 总 ~210ms (省 ~150ms)
