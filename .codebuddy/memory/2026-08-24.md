- 修复 `Uncommitted Changes` 虚拟提交始终置灰：根因是 `UncommittedFilesWatcher` 可能在 `GitCommitController` 接收 selected branch 前完成初始发布，而提交控制器只订阅后续事件，导致 `workingTree` 一直为空。现在 `GitCommitController.selectBranches()` 落地 current branch 后直接通过 `UncommittedFilesWatcher.getUncommittedFilesByHeadBranch()` 同步快照，并校验 repoPath/hash 后更新 presence；不再由 Provider 重新读取 Git 状态。`npm run compile` 与 IDE diagnostics 通过。
- 修复虚拟提交持续显示“正在加载变更文件”：`GitkViewProvider.selectWorkingTreeChanges()` 首次调用没有传入事件参数，却在写入 store 时错误访问可选参数 `changes.staged/changes.changes`，抛出 TypeError，导致 `filesLoading` 未被清除。改为始终使用已解析的 `workingTreeChanges`；`npm run compile` 与 diagnostics 通过。
- 已撤销将 stage/unstage/discard 与 `UncommittedFilesWatcher` 绑定的共享 Git 队列方案；该方案只序列化本扩展的一部分操作，不能消除外部 Git 进程或已遗留 `.git/index.lock`，且扩大 watcher 职责。最终无锁 watcher 方案：`UncommittedFilesWatcher` 文件事件只作为刷新信号，排除 `.git/**` 后不再运行 `git check-ignore`；Git status 的结果天然不含 ignore 文件。`getWorkingTreeChanges()` 的 `status`、`diff --cached`、`diff` 三条只读 CLI 均显式带 `--no-optional-locks`，防止 watcher 读取路径创建 optional Git locks。写操作仍按 Git 原子锁语义运行；`npm run compile` 与 diagnostics 通过。
- `UncommittedFilesWatcher` 已补充每仓库真实 git-dir 的 `index` 文件 watcher：通过无 optional locks 的 `git rev-parse --absolute-git-dir` 定位 git-dir，工作区 watcher 继续排除 `.git/**`，index watcher 独立触发同一仓库 `running + needsRefresh` 刷新槽，确保外部 stage/unstage 等只变 index 的操作也刷新 staged changes。index watcher 创建本身按 repoPath 单飞去重，create/change/delete 三种文件事件都仅进入该刷新槽：在途时只置一次 `needsRefresh`，后续重复事件忽略，完成后至多补读一次。两类 watcher 均在 current HEAD 移除和 dispose 时释放；`npm run compile` 与 diagnostics 通过。
- 修复 `restore --staged` pathspec 不匹配的状态根因：Provider 之前在 Git 写入前乐观把 UI 文件从 staged 移到 unstaged；当真实写入失败或 watcher 快照尚未回填时，后续“全部 Unstage”会把非暂存的路径传给 `git restore --staged`，报 pathspec 未被 Git 追踪。已移除乐观分区更新，Changed Files 仅由 `UncommittedFilesWatcher` 的真实 Git 快照更新；单次操作失败后立即请求 watcher 回填真实状态。`npm run compile` 与 diagnostics 通过。
- 已删除 `GitkViewProvider` 中重复且过宽的全局 `**/.git/index` watcher；它与 `UncommittedFilesWatcher` 的真实 git-dir/index 精确监听职责重叠，并可能诱发 VS Code 对普通文件派生 `<file>.git` 的 ENOENT lstat。Provider 不再监听全局 index；`npm run compile` 与 diagnostics 通过。
