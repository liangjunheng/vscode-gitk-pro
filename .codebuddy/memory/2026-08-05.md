# 工作记录 - 2026-08-05

## Multi-Diff 文件定位

- 已弃用直接调用 `vscode.open` 打开内部 `multi-diff-editor:` URI 的方案：该方案会造成编辑器打开异常。
- 改为复用 `_workbench.openMultiDiffEditor`：同一 commit 内点击文件保持既有资源顺序，并传递 `reveal: { modifiedUri: targetUri }` 请求定位目标资源。
- `npm run compile` 通过，`src/commitFilesViewProvider.ts` 无诊断。
- 修复 Multi-Diff 定位后文件列表高亮误选：活动编辑器变化时直接按其 Git URI 同步；可见编辑器变化只有唯一当前提交 Diff 时才同步，避免 `visibleTextEditors[0]` 在多条目可见时覆盖点击目标。
- VS Code 公共 API 的 `visibleTextEditors` 仅给出可见文本编辑器集合，不保证 Multi-Diff 视口内项目的顶部顺序；没有公开的 Multi-Diff 滚动位置或“首个可见资源”事件，因此不能据此可靠地随滚动高亮首项。`onDidChangeVisibleTextEditors` 可以感知集合变化；扩展可自行比较前后集合推断某 URI 从可见变不可见，但无法推断其在 Multi-Diff 视口中的具体位置或滚动方向。
- 按用户要求实现启发式同步：保存当前提交上轮可见路径；若单一路径从集合消失，则取其在 `this.files` 中的下一个文件，且该文件仍在新可见集合时将其作为首项高亮。若单一路径从不可见变可见，且其在提交顺序中正好位于已知首个可见项之前，则将它设为新的首项高亮。多个路径同时变化或不满足相邻条件时不变更高亮；`npm run compile` 和该文件诊断通过。
- Changed Files 面板失去可见性时不再关闭 Multi-Diff：点击文件导致面板失焦时旧逻辑会清空 `openedDiffHash`，使下次点击误判为需要重新打开。为恢复同一提交内文件跳转，保留既有 Multi-Diff 并再次调用 `_workbench.openMultiDiffEditor` 携带相同资源和 `reveal: { modifiedUri }`；这会请求 VS Code 定位目标条目，不关闭旧 Diff。
- 可见 Multi-Diff 编辑器监听每次 `onDidChangeVisibleTextEditors`，比较上一轮和当前集合并记录 `added` / `removed` 文件名日志。由于公开 API 的集合顺序不可靠，链表改为每次按 `this.files`（Changed Files 的原始顺序）从当前可见集合重建，头节点和高亮均严格匹配文件区顺序；Git URI 会规范化为 `CommitFile.path`，以兼容重命名文件。每次 Visible 事件都会从头节点沿 `next` 遍历，并仅输出文件名。
- Tree 模式按 `files` 原始顺序将连续同目录文件归为 `<details>` 可折叠组；选中文件所在目录自动展开，保证高亮可见。`npm run compile` 通过且无诊断。
- 为核实 Multi-Diff 视觉可见项与 API 返回集合的差异，`syncHighlightFromVisibleDiff` 在每次 VisibleEditor 回调输出所有编辑器的完整 URI、scheme、当前提交匹配结果、解析路径和规范化路径；保留原有 added/removed 与链表文件名日志。`npm run compile` 通过且无诊断。
- 核实 VS Code Multi-Diff 内部实现：编辑器窗格没有运行时 add/remove/update resources 方法；是否可动态更新取决于内部 source/view model，且未向扩展公开。当前扩展通过 `_workbench.openMultiDiffEditor` 传入完整 `resources`，不具备受支持的增量加载接口。
- 已以 `src/customDiffPanel.ts` 的 `CustomDiffPanel` 替换原生 Multi-Diff：`CommitFilesViewProvider.openDiff` 打开 WebviewPanel；面板按文件占位项的 `IntersectionObserver` 视口接近事件分批请求内容，扩展侧再按需以 git URI 读取父提交/当前提交文本。文件头点击回传路径同步 Changed Files 高亮。移除了原生 Multi-Diff 的不可用可见编辑器链表监听。
- 自定义 Diff 已重构为接近 VS Code Diff Editor 的视觉与交互：工具栏可切换并排/内联；文件区有状态标识、折叠箭头和改名前路径；差异以 LCS 行级对齐显示行号、删除/新增色块与 `−`/`+` 标记。超大文件跳过 LCS 计算并按原始行渲染，避免二次卡顿。
- 修正自定义 Diff 样式错乱：字体、字号、字重、行高、前景/背景、行号栏、Git 状态和增删行颜色均直接使用 `--vscode-*` 编辑器主题令牌，移除硬编码色值和字号回退；修正统一/并排模式下 pane 显隐与行网格列数。
- 自定义 Diff 现默认折叠未变更区段：只显示每个变更区段前后各 5 行；文件开头/末尾没有对应方向的额外上下文。中间省略部分以主题化“展开 N 行未更改内容”按钮显示，点击会在当前文件内展开完整区段。`npm run compile` 通过，`customDiffPanel.ts` 无诊断。
- 自定义 Diff 新增 sticky pinned 当前文件栏：从 Changed Files 选择文件会定位并更新 pinned；点击 Diff 文件头会更新 pinned 并回传高亮 Changed Files；点击 pinned 会回到对应 Diff。相同提交内重复选择只发送 `selectFile`，不重置已懒加载的内容。`npm run compile` 通过，`customDiffPanel.ts` 无诊断。
