- **同一 bug 的第三种形态及最终修复（点刷新按钮后分支塌成一条）**：上条重构只替换了 `refreshSelectors` 仓库选项变化分支里「后台补全」那半段，却留下了前半段把 `this.branches` 砍成「已选 + 当前分支」的赋值（单选当前分支时去重后只剩一条）。原代码里砍短是安全的，因为紧接的 `fullBranchesPromise.then` 共享同一 signal 会立刻补回；替换成独立的 `refreshBranchesAfterRepositorySelection`（且当时未传 signal）后，砍短与补全之间的窗口暴露出来。触发时机正是子模块扫描完成使 `repositoryOptionsChanged` 翻 true 的那一刻，故表现为「仓库刷新结束后分支塌成一条」。最终修法：删掉整段清空重建，只留 `void this.refreshBranchesAfterRepositorySelection(selectedRepositoryPaths[0], signal)`；理由是该场景下当前仓库并未改变，分支根本不需要清空，`getGitBranches` 返回的就是完整列表。同时给该方法补 `signal` 参数并纳入 `isCurrent()` 门禁。
- **根本教训（三次返工的共同错误）**：每次都在修「中间态显示成什么」，而没有质疑「这个中间态是否必要」。凡是「先砍短/清空 → await IO → 再补全」的写法，中间态存在多久就会闪多久；若该场景下数据本无需清空（如同仓库内的分支），正确做法是直接等完整结果整体替换。切仓库快路径的单条当前分支是必要中间态（旧仓库分支必须立即清除），予以保留。
