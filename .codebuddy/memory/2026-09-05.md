## 关键约定

- 片段模块导出 `*_STYLES` / `*_MARKUP` / `*_SCRIPT` 字符串常量, 由 document 模块的 render 函数用 `${}` 拼装。
- **所有脚本片段拼进同一个 IIFE**, 因此函数声明提升与 `let/const` 作用域共享都保持原样, 跨片段调用无需改动。
- 归属规则(避免循环依赖): **谁拥有 DOM 元素, 谁就持有它的监听**。片段之间互不 import。
- 片段顺序约束: 含 `const/let` 状态声明的片段必须排在会同步执行的代码(骨架尾的 `render(initial...)`)之前, 否则撞 TDZ。
- 状态归属: 谁写谁持有, 只读方靠闭包共享。

## gitk 视图改为上下布局 (变更文件列表在上, Commit 列表在下)

- 用户要求: 不要左右分栏, 改成上下。涉及 `gitkWebviewDocument.ts` 四处, 缺一不可:
  1. `#workspace`: `grid-template-columns: minmax(180px,1fr) 5px minmax(180px,1fr)` → `grid-template-rows: ...` + `grid-template-columns: 100%`。
  2. `#panelResizeHandle`: `cursor: col-resize` → `row-resize`。
  3. 结构顺序改为 CHANGED_FILES → handle → COMMIT_LIST; 无障碍语义 `aria-label="调整变更文件列表与提交图高度"`、`aria-orientation="horizontal"`。
  4. 拖拽逻辑由 X 轴改 Y 轴: mousedown 存 `startY/topHeight/totalHeight`(量 `#filesSection`), mousemove 写 `gridTemplateRows`。
- 只改这四处就够: `#filesSection`(flex column + `#filesList` flex:1) 与 `#graph`(overflow:auto) 本身都带 `min-height:0`, 纵向栅格下无需再调; 提交图列宽拖拽走的是另一套 `resizing` 状态, 与 `panelResizing` 无关, 不受影响。
- 端到端校验: 把上述改动加入期望侧变换表后, 三处仍全部 OK, 证明除布局外无其他漂移。

## 上下布局再补: 铺满宽高

- `#workspace`: 行/列都改用 `minmax(0, 1fr)`(原来是 `minmax(180px, 1fr)`, 空间不足时会超出可视区), 并加 `width: 100%`。拖拽写入的 `gridTemplateRows` 同步改成 `minmax(0, 1fr)`, 保证拖动后仍严格铺满。
- `#filesSection` / `#graph`: 各加 `width: 100%; height: 100%;`, 显式占满栅格区域。
- `#graph` 改成 `display: flex; flex-direction: column`, 新增 `#commitList { flex: 1 0 auto; min-width: 0; }`; `.commit-header`/`#loading`/`#commitFooter` 加 `flex: 0 0 auto`。
- **关键坑**: `#commitList` 必须是 `flex: 1 0 auto`(grow=1, shrink=0), 不能是 `flex: 1 1 auto`。`#commitList` 自身没有 `overflow`, 若允许收缩, 内容超高时会被压扁到比内容还矮, 滚动就废了。收缩只适用于自身带滚动的 `#filesList`(`flex: 1 1 auto` + `overflow-y:auto`)。
- 校验脚本的坑: 期望侧变换表若在"逐行"上做替换, 多行替换结果会破坏行级多重集比较; 改成在合并文本上替换再切回行。

## 事故 1: multiDiffPanelDocument.ts 的修改被静默回退

- 现象: 第 4 轮修好 `${webview.cspSource}`→`${cspSource}` 且编译通过后, 第 5 轮再编译又报 4 个 TS2304。
- 排查(逐项排除): `scripts/copy-monaco.cjs` 只写 `media/`(碰不到 src); 该文件在 git 里是 untracked, 没跑过 checkout/stash; 重新修好后连续 3 次读取 MD5 完全一致, 编译通过。
- 结论: 回退来自构建之外(工作区在 OneDrive 下, 与既有 OneDrive 事故记录一致)。
- 教训: 脚本生成的文件后续再改, 改完必须重新读取/校验再信任; 大批量重构结束跑一次端到端等价校验, 能一次性抓出这类静默回退。
