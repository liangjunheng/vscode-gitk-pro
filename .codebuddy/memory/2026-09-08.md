## 修复: 外部命令行 commit 后提交列表不刷新 (src/git/eachRepoHeadBranchWatcher.ts)

**现象**: 外部终端 git commit 后, gitk 的 commit 列表不出现新提交(工作区未提交区会变, 提交列表不变)。

**根因链** (两处叠加, 都在 RepoHeadBranchWatcher):
1. `createHeadWatcher` 只监听 `.git/HEAD`。HEAD 存的是符号引用 `ref: refs/heads/x`,
   commit/amend/merge/rebase/reset 都只改写目标 ref 与 `logs/HEAD`, 不触碰 `.git/HEAD`
   (detached HEAD 除外)。所以 HEAD 值变化的信号源根本没进系统。
2. `getHeadBranchByRepo` 有 `if (cached) return cached;` 短路。唯一调用方
   `SelectedRepoTotalBranchWatcher.drainRefresh` 是在 refs 已被改写之后来取 HEAD 的,
   必然拿到旧 hash; 用它组装的 complete 快照与 previous 逐项 equals 相等
   (`GitBranchOption.equals` 比 hash) → `continue` → 不发 `onRepositoryBranchesChanged`
   → GitBranchesController 不 fireSelected → GitCommitController.selectBranches 不被调用。

**改动**:
- `getHeadBranchByRepo` 去掉缓存短路, 始终 `enqueueHeadRead` 取真值 (有 slot 合并 + needsRefresh 重跑)。
  缓存语义只保留给 `getCachedHeadBranch`(初始化回填场景)。
- `createHeadWatcher` pattern `'HEAD'` → `'{HEAD,logs/HEAD}'`。logs/HEAD 是 HEAD 移动的唯一权威记录;
  对 linked worktree 更是必需: `rev-parse --absolute-git-dir` 返回 `.git/worktrees/<name>`,
  而 `refs/heads/**` 在 common dir, SelectedRepoTotalBranchWatcher 的 refs watcher 在 worktree 下失效。

**收敛性论证**: logs/HEAD 若先于 ref 提交到达, 读到旧 H1 时 previous 也是 H1 → 不 fire; ref 事件
到达后 drainRefresh 读真值 H2 → fire。中间无倒退窗口。

**未改**: `GitBranchesController.applyTotalBranches` 的 fireSelected 判据仍是 headChanged
(选中非当前分支的 hash 变化不会下发给提交控制器) —— commit 场景下 HEAD 必然变, 已覆盖, 未扩大改动范围。

**内部 commit 原有路径保留**: gitkViewProvider.runCommit 仍显式
`uncommittedFilesWatcher.refreshHeadBranch()` + `commitController.forceRefreshCurrentSelection()`,
其必要性由"同步等新 HEAD 的 staged 清单就绪"支撑, 与本次 watcher 修复不冲突。
