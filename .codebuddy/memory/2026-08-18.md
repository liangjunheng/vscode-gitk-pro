## MultiDiffPanel 卡片化 + pinned 标题栏 + 折叠/联动（参考 customDiffPanel）

参考源：`git show 28d8cc2^:src/webview/customDiffPanel.ts`（旧面板已在 28d8cc2 删除，需要时用 git show 取回）。

改动文件：`src/webview/multiDiffPanel.ts`（重写 HTML/CSS/JS 与消息协议）、`src/webview/gitkViewProvider.ts`（注入回调）。

### 1. 卡片式
- 每个 diff 渲染为 `<section class="diff" data-path data-index>`，内含 `.file-header` + `.diff-body > .editor`。
- 卡片：`--card-radius:8px`、`--card-border:1px`、`box-shadow:0 1px 4px`，`.diff.selected` 用 `--vscode-focusBorder` 描边。
- body 背景改 `color-mix(in srgb, var(--vscode-editor-background) 50%, #000)`，卡片自身用 editor background，形成卡片浮起效果（沿用 customDiffPanel 做法）。

### 2. 标题栏（rename + 贴合卡片但排除边缘）
- 内容顺序：chevron SVG → `.status`（A/M/D/R 用 gitDecoration 颜色）→ `.line-stats`（+added/-removed）→ `.file-path`（folder 前缀灰色 + ellipsis）→ `.rename`（`← oldPath`，仅 oldPath !== path）。
- 修正（同日）：用户明确要求移除标题栏最前面的序号页码，已删除 `.diff-index` badge 及其 CSS，`headerHtml(diff)` 不再接收 order/total，`createCard(diff,order)` 的 order 仅用于 `data-index`。
- 贴合关键点：`.file-header` 无自身左右/上边框，`width:100%` 落在卡片 border 内沿；顶部圆角用 `calc(var(--card-radius) - var(--card-border))` 与卡片圆角内切；只有 `border-bottom` 作分隔线。这样顶部、两侧、圆角都贴合，但不覆盖卡片边框本身。
- `.diff-body` 用底部同样的内切圆角 + `overflow:hidden`，保证 Monaco 不溢出圆角。

### 3. pinned 逻辑
- `.file-header{position:sticky;top:0;z-index:2}`。
- `updatePinned()` 遍历卡片，`rect.top<=0 && rect.bottom>headerHeight` 时加 `.pinned`（额外阴影），滚动经 rAF 节流调用。

### 4. 折叠 / 双向联动
- 点击标题栏 → `toggle(entry)`：切 `.collapsed`（`.diff-body{display:none}`，标题栏恢复四角圆角、下边框透明，chevron 旋转 -90deg）；展开后 `requestAnimationFrame(entry.fit)` 重算 Monaco 高度。
- Diff → Changed Files：滚动时 `topVisibleCard()`（第一个 `rect.bottom>1` 的卡片）→ `setActive(path,true)` → postMessage `{type:'selectFile',path}`；MultiDiffPanel 构造函数新增可选 `onSelectFile`，gitkViewProvider 注入 `syncFileHighlightFromDiffPanel`，回写 `store.selectedPath`。
- Changed Files → Diff：Provider `selectChangedFile` → `openDiff` → `MultiDiffPanel.show(revealPath)`。show 对已就绪面板**只发** `{type:'reveal',path}`，不重建 Monaco 编辑器（避免每次点击全量重建）。
- `suppressSyncUntil` 时间窗抑制程序化滚动回灌 selectFile，防止循环。

### 5. 滚动动画改为定时长（修正原生 smooth 的按距离计时）
- 问题：`window.scrollTo({behavior:'smooth'})` 由浏览器决定时长，距离越远耗时越长，观感是「慢」且不同距离时长不一致。
- 方案：自实现 `animateScrollTo(top)`，rAF 逐帧插值，常量 `SCROLL_DURATION=300`（ms）固定总时长，距离远时自动提速；缓动用 easeInOutQuad（`progress<.5?2p²:1-(-2p+2)²/2`）。
- 细节：进入动画先 `cancelAnimationFrame` 上一次动画防叠加；每帧调 `updatePinned()` 让 sticky 标题栏状态跟随；距离 <1px 直接跳；`reveal(path,false)` 仍走瞬时 `behavior:'auto'`；`suppressSyncUntil = now + SCROLL_DURATION + 120`。

### 7. 并发加载 + 全部完成才展示
- 先纠正一个认知：数据层原本就是「全读完才展示」——`DiffReader.prepare` 只在所有批次结束后才 `store.setState({files:data,diffLoading:false})`，中途不写 files。真正逐个跳动的是 webview 里每个 Monaco DiffEditor 的**异步差异计算**（`onDidUpdateDiff` 后才有真实高度，`fit()` 才撑开卡片）。所以要两层都改。
- 数据层（`src/git/diffReader.ts`）：批次从 for 串行 await 改为先切 `batches` 再 `Promise.all` 并发；每批完成累加 `completed` 更新 `diffProgress`；结束后 `results.flat().sort((a,b)=>a.index-b.index)` 恢复文件顺序（并发完成序不定，必须排序）。
- 关键配套：`readGitObjects` 原来用单个 `this.childProcess` 字段，并发下后启动的会覆盖前一个引用，导致 `stop()` 杀不干净、遗留 git 进程。改为 `private childProcesses = new Set<ChildProcess>()`，spawn 时 add、error/close 时 delete、`stop()` 遍历 kill 后 clear。
- 渲染层（`src/webview/multiDiffPanel.ts`）：`createCard(diff,order,parent)` 改为返回 Promise，以 `editor.onDidUpdateDiff` 首次触发为就绪信号，并带 `CARD_READY_TIMEOUT` 超时兜底；error/binary 卡片直接 resolve。`render()` 用 `Promise.all` 等全部就绪后才显示；期间 loading 显示「正在渲染 Diff (ready/total)...」。`renderToken` 递增用于丢弃过期渲染批次。

### 8. 「加载 commit 变久」的回归修复（同日）
用户反馈上一步改完后选 commit 明显变慢，定位到三点并按其要求处理：
- 主因（固有代价）：`Promise.all` 的耗时等于**最慢**那张卡片，而就绪信号是 Monaco 异步 `onDidUpdateDiff`。`CARD_READY_TIMEOUT` 先按用户要求从 4000 改为 15，随后用户再次要求改为 **15000**（最终值）。语义随之回到「完整等待差异计算完成，15s 仅作卡死兜底」，即优先保证展示时零跳动，接受首屏等待更长。若日后又觉得慢，只调这一个常量即可。
- 次因一（已修）：原实现把卡片建在离屏 `DocumentFragment`，此时 `host.clientWidth` 为 0，Monaco 首轮 layout 用错宽度，挂载后不得不补两轮 `entry.fit()`，N 个编辑器开销可观。改为**卡片直接 append 到 `#list`**（保证真实宽度，一次 layout 到位），渲染期间用 `#list.rendering{visibility:hidden}` 仅做视觉隐藏；完成后移除 class 即可，删掉了 `replaceChildren(fragment)` 与两轮补偿 `fit()`。注意 `visibility:hidden` 而非 `display:none`，后者会让宽度重新变 0。`show()` 里同步 `classList.remove('rendering')` 防止残留。
- 次因二（已修）：`batchSize` 是 128，文件数 ≤128 时切批 + `Promise.all` 纯属额外调度开销（多数 commit 都在此区间）；文件数超 128 时并发 spawn 多个 `git cat-file` 也可能因进程创建与磁盘竞争变慢。现 `prepare()` 增加 `total <= batchSize` 快路径，直接单次 `readDiffs` 后写回，跳过切批与排序。
